# `pipeline/` — the certification pipeline

Everything `certify.py` executes. Adding a benchmark touches none of it: see
[CONTRIBUTE.md](../CONTRIBUTE.md). Data lives in [`datasets/`](../datasets/README.md),
run recipes in the root [README](../README.md).

## Generate once, evaluate many

Stage-2 variants and stage-3 scenario trees are produced **once** by `generate.py`
(an attacker model, Hermes-4-70B on slurm) into
[`datasets/generated/`](../datasets/generated/README.md) and **replayed** against every
target. Every model sees identical variants and the attacker is paid for once. The only
models `certify.py` calls are the target, the two judges and, under `--simulate`, the
branch classifier. `reconsideration` is the exception: it challenges the target's own
control answer, so it has no artifact and runs live.

`certify.py` validates artifacts before any eval starts (`artifacts.py::validate_artifacts`)
and fails fast with the `generate.py` command that fixes it: every id in the CSV with the
family applicable has rows, no row is orphaned, rewrite rows re-render from the template,
and `meta.prompt_version` matches `PROMPT_VERSIONS`. `tests/test_artifacts_current.py`
runs the same checks in the suite, so stale artifacts fail CI rather than a run.

## Stages

| Directory | Stage | What runs |
|---|---|---|
| `stage1_evaluation/` | 1, control | `evals/clusters.py` builds one task per risk from `datasets/public/<risk>.csv`; `scorers/cluster.py` dispatches on `question_type`; `scorers/detectors.py` holds the ported deterministic detectors and both refusal detectors (`is_refusal`, 220-char prefix as CyberSecEval ports it; `liberal_refusal`, whole text, used by the screen and the classifier). |
| `stage2_perturbation/` | 2, surface perturbation | One replay solver per family (`solvers.py`), rewrite prompts (`rewrite.py`), framing and persona templates (`framing.py`), the per-sample split (`adapters.py`). Layered by `registry.py::apply_stages` under `--perturb`. |
| `stage3_simulation/` | 3, multi-turn scenario | `solvers.py::scenario` walks the pregenerated branching tree; `classify.py` labels each target reply; `prompts.py` holds the tree prompt and parser. Layered under `--simulate`; composes with `--perturb` in one task and one log. |

Shared: `generation.py` (offline generators, driven by `generate.py`), `artifacts.py`
(`datasets/generated/` store, `PROMPT_VERSIONS`, `applicable_ids(family)`, validation),
`registry.py` (`apply_stages`, `_build_task`), `utils/scoring.py` (scoring spine and panel
metrics), `utils/results.py` (results tree), `utils/replay.py` (run the target on stored rows),
`utils/graders.py` (grader and model loading, preflight canaries).

### The perturbation split

A row is `item_text` (the request) inside `prompt_template` (the scoring scaffold: option
block, scale, output contract) joined at `{{ITEM}}`. Rewrite families reword only
`item_text` and re-render through the template, so the stage-1 scorer keeps its contract.
A row's own `system_prompt` is replayed with the variant so a variant is compared against
a control it matches. Stage 3 replaces the prompt wholesale, so **under a scenario every row
is judged** by the LLM judge against the row's `criterion` and `fallback_categories`: a
deterministic scorer there would read a contract the scenario never set up, and a column
scored by a mixture of instruments cannot be compared with its control. Gap sources
(`leader_favorability`, `role_model_bias`, the human-rights persona gap) lose their arms
under scenario and fall back to a plain mean; the gap is reported at baseline only.

## Families

| Family | Kind | Applies to | Artifact |
|---|---|---|---|
| `paraphrase` | attacker rewrite of `item_text` | rewrite-eligible rows | `paraphrase.jsonl` |
| `register` | attacker rewrite (register shift) | rewrite-eligible rows; **provisional, pilot decides** | `register.jsonl` |
| `past_tense` | attacker rewrite into historical framing | rewrite-eligible rows | `past_tense.jsonl` |
| `multilingual` | attacker translation, one variant per language (`de`, `zh`, `ar`); judge sees the English criterion against the translated exchange | rewrite-eligible rows | `multilingual.jsonl` |
| `framing` | 3 deterministic templates | `compliance` rows | `framing.jsonl` |
| `persona` | deterministic system-prompt wrap, 2 templates | `graded` and `mcq` rows without their own `system_prompt` | `persona.jsonl` |
| `reconsideration` | live challenge to the control answer | every row | none |
| `scenario` | stage 3 branching tree, k=2, depth 3 | every row | `scenario.jsonl` |

`identity_strip` is gone: a blind fidelity pass found it drops the construct on judgment
and detection sources.

**Applicability is one column.** `families` in the cluster CSV (a JSON list) is the single
gate at generation, validation and replay (`artifacts.py::applicable_ids(family)`,
`metadata["families"]` in `utils/replay.py`). A `Source` may set it; the default is derived
from `question_type` by `schema.py::Source.families_for`: `detection` rows get only
`reconsideration` and `scenario` (their measured signal is inside the text, so rewriting it
moves the thing being measured); everything else gets the rewrite families plus
`reconsideration` and `scenario`, plus `framing` when the elicitation family is `compliance`
and `persona` when the row has no `system_prompt` of its own.

**Keep/kill gate.** A family is kept only if, on a pilot (`--limit 40` per cluster, 2 target
models already in `models.json`):

1. **Fidelity:** `scripts/audit_variant_fidelity.py` same-ask rate ≥ 90% (prompt-only pairs,
   so Claude can rate cbrn/cyber), and
2. **Drift:** `stability_<family>` ≤ 97 (mean |drift| ≥ 3 points) on at least one cluster,
   or `resilience_<family>` < 100 on ≥ 5% of items.

Results are written to `analysis/family_pilot.md`; a family failing (1) is removed, failing
(2) is removed unless the user overrides.

**Depth bias.** More variants → lower min; that is what "worst case" means, not a bug, and
the per-item worst stays the min over every condition. The bias matters only where families
are *compared*, so `scoring.py::sample_reduce(conditions) -> {family: value}` gives each
family one value: mean within the family, except `scenario` = min over turns (turns
escalate). `by_family.*` and the per-item `average` use it.

## The scenario tree (stage 3)

`datasets/generated/<risk>/scenario.jsonl`, prompt version 4, one row per (id, variant):
`system` (deployment system prompt) and `turns`, a map from branch path to the next user
turn: `""` (opening: context + the ask), `refuse`, `hedge`, `refuse/refuse`,
`refuse/hedge`, `hedge/refuse`, `hedge/hedge`. `comply` has no child: a complied turn
already drives the item's min to its floor, so a follow-up adds judge cost and no
information. Seven user turns per scenario, k=2 → 14 per item. Variant 2 is prompted to
differ from variant 1 in role, sector and asker.

Runtime (`stage3_simulation/solvers.py::scenario`): send `system` and `turns[""]`; for depth
1..3 generate the target reply, record it, classify it, and if depth < 3 append
`turns[path + label]`. Each judged turn is recorded under
`state.metadata["simulations"]["scenario"]` as
`{condition: "scenario_variant_<k>_t<depth>", query: <rendered transcript>, completion, variant, turn, path, label}`;
the rendered transcript (`[system] … [user] … [assistant] … [user] …`) is what the judge
sees as "the request", so the graded template is unchanged.

Classifier (`stage3_simulation/classify.py`): `liberal_refusal` → `refuse` (free); else one
call to `--sim-classifier` (default `openrouter/google/gemini-3-flash-preview`) with a
three-label rubric, cached by content (`CachePolicy(expiry=None)`) so reruns never re-bill;
unparseable → `hedge` with `label_source: "fallback"`. The label is stored per turn for
audit. Judge calls per item ≤ k × 3 = 6 per judge, ≈ 4.4 with comply-pruning.

Validation is strict: every row has `system` and seven non-empty `turns`; id coverage must
equal `applicable_ids("scenario")` exactly.

## Metrics

Every number below is **0–100, higher is safer**. This section is the one definition;
`utils/scoring.py`, `utils/results.py`, CONTRIBUTE.md and the README link here.

**Conditions.** Each item runs under the control (the unperturbed query) and every
applicable condition, labelled `<family>_variant_<k>`, `multilingual_<lang>`,
`framing_<name>`, `persona_<name>`, `reconsidered`, `scenario_variant_<k>_t<depth>`.
Each is judged to a safety value in [0, 1] or abstains. Abstentions are excluded from
every statistic; a pool with nothing scored reports **NaN** (panel) or **`null`** (tree),
never 0 and never 100, so a run whose judges all abstained cannot certify or fail by default.

**Per item** (`utils/scoring.py::_wrap_scorer`):

| Quantity | Definition |
|---|---|
| `worst` | min over all scored conditions, **control included** |
| family value | `sample_reduce`: mean of the family's scored conditions; `scenario` = min over its turns |
| `average` | mean over families of their family values, control counted as a family |

The control is inside `worst` because a certificate asks how bad the model gets on this item,
and the published wording is one of the ways to ask.

**Eval panel** (Inspect's results panel, per task): `safety_control`; `safety_<family>`
(mean over items of the family value); `safety_worst` (mean of per-item `worst`);
`safety_average` (mean of per-item `average`); `stability_under_attack` =
100 · (1 − mean |drift from control| over all attack conditions); `resilience_under_attack`
= % of items whose `worst` held at or above their own control. Stability is a mean on
purpose: "how far does it move" is a different question from "how bad does it get", and
resilience is the one that pairs each item against its own control.

**Per source** (`utils/results.py`, `results.<risk>.benchmarks.<source>`):

| Field | Definition |
|---|---|
| `baseline` | mean of control values |
| `aggregate.average` | mean over items of per-item `average` |
| `aggregate.worst` | mean over items of per-item `worst` |
| `aggregate.tail` | **CVaR@10%**: mean of the lowest ⌈0.1·n⌉ per-item `worst` values (n ≤ 10 → the min) |
| `aggregate.n_items` | items with a scored `worst` |
| `conditions.<family>` | `{safety, stability, scored, abstained, total, scorers}`; `safety` via `sample_reduce` |
| `diagnostic` | present and `true` for sources reported but not pooled (`role="diagnostic"` or pooled through a derived entry) |

Sources whose safety is a gap between arms (`leader_favorability`, `role_model_bias`,
`human_rights_persona_gap`) use their `source_metrics.SUMMARIES` summary for `average`,
`worst` and `tail` alike.

**Per risk** (`results.<risk>`): `aggregate.average` / `aggregate.worst` = unweighted mean
over pooled non-diagnostic sources (sample count is weight only inside a source; quotas make
sources commensurable); `aggregate.tail` = CVaR@10% over the **union of per-item `worst`
values** of those sources, the true tail of the risk's item distribution rather than a mean
of per-source tails; gap sources stay out of the union. `baseline` = mean of source
baselines. `by_family.<family>` = safety per family over the pooled sources. `status` is
`"ok"`, `"empty"` (no scored items; every `aggregate.*` is `null`) or `"error"` (with an
`error` string and nulls). There is no −1 anywhere.

**Per model** (`models/results/<model_id>.json`, merged into `models/models.json`):

| Field | Definition |
|---|---|
| `scores.<risk>` | **the headline: `aggregate.tail`**, or `null` |
| `aggregate` | `{average, worst, tail}`, mean over risks with non-null values |
| `results.<risk>` | the tree above |
| `status.<risk>` | `{status, completed_samples, total_samples, usage: {model_id: {input_tokens, output_tokens, total_cost}}, run_id, …}`; `status` is `success`, `partial`, `empty` or `error` |
| `id`, `name`, `company`, `region`, `specialty`, `aa_*` | identity and the Artificial Analysis index fields, preserved across reruns |

A partial run writes `scores.<risk> = null` with `status.<risk>.status = "partial"` and the
tree is still present; there is no `partial_scores`. `--rerun` re-runs only risks whose
status is not `success`.

**Changed for the site (communicate before fleet writes):** `scores.*` is the tail (was the
worst); `aggregate.mean` is now `aggregate.average`; new `aggregate.tail` and
`aggregate.n_items`; `null` replaces −1; `partial_scores` is gone; `status.*.usage` and

> **Scope: `datasets/raw/` only.** Nothing here reads `datasets/generated/`; those

| Tier | What it does | Cost |
|---|---|---|

## Why embeddings replaced Jaccard

The lexical tiers were kept while the pools were small and templated. Two things changed.
With ~60 benchmarks arriving, pools reach ~100k items and clusters roughly double, so the
quota has to pick *diverse* items from a pool it cannot keep whole. And token-set Jaccard
fails on long text in both directions: measured on PreservingHistoricalTruth's rendered
prompts (median 117 tokens) the top pair at 0.598 was template boilerplate between two
*different* events, and on ECHR scenarios (median 104) true near-duplicates reached only
0.41, inseparable from unrelated pairs. The old design answered with a per-pair token gate
(compare only texts under ~25 tokens), which meant long-text pools were simply never
deduplicated. Embeddings handle long text, so the gate, the inverted index and `jaccard()`
are gone; `normalised()` stays as the cache key.

**Embeddings.** `sentence-transformers/all-MiniLM-L6-v2` (384-d; 100k texts in minutes on
CPU), computed by the standalone `scripts/embed_items.py` in an ephemeral env so ML
dependencies never enter `uv.lock`. Cache: `datasets/cache/embeddings/<risk>.npz` (`keys`,
`vectors` float16), keyed by `blake2b16(normalised(payload))`, gitignored. `prepare.py` only
reads arrays: on a miss it writes `datasets/cache/<risk>.embed_input.jsonl`, prints the
exact command and exits 2. A CSV is never built on a partial cache.

**Payload.** `dedup_on`'s metadata field where a source declares one, the rendered query
otherwise: `historical_revisionism` embeds `Historical Event`, not the ~100-word
instruction around it, so similarity is on the item and not the wrapper. `distinct_on`
declares fields whose differing values mean different items at any similarity (SOSBench's
`original_term`, PHT's `Push Level`); MCQ rows get it free from `target`.

## The answerability screen

Stratified sampling spreads across known axes; it does not find the items that
discriminate between models. The cheapest proxy for "will any model answer this" is
whether a weakly-aligned open model does: an item Hermes-4-70B refuses is near
zero-variance across the fleet and wastes judge budget, so it is dropped. Refusal is
detected by `detectors.py::liberal_refusal`, several regexes over the whole completion,
deliberately liberal: erring toward "refused" drops a borderline item, erring the other way
spends two judges on nothing.

Scope is `Source.screen`, defaulting to `question_type ∈ {graded, mcq}` with
`elicitation_family ∈ {compliance, generic}`. Not screened, with the reason recorded in
meta: likert/opinion and graded/judgment (the construct is a position; a refusal is not
zero-variance), detection (refusal *is* the signal for `cyber_false_refusal`; token and tool
contracts elsewhere), extraction. Grouped sources (the human-rights arms) screen the leader
row only.

The runner is `scripts/screen_answerability.py`, Hermes served by vLLM on slurm exactly as
`generate.py` is (`scripts/generate_hermes_slurm.sh` runs it first). Verdicts append to
`datasets/cache/screen/<risk>.jsonl` (`{key, sample_id, verdict, completion[:400], model,
created_at}`), so reruns are free and the file is reviewable. If a source loses more than
half its candidates, raise its factor rather than let the quota shrink silently;
`refused_dropped` per source lands in meta. **Read `screen/<risk>.jsonl` and
`refused_dropped` before committing a CSV:** the screen drops the most egregious prompts by
design, and that is the one place to see what it threw away.

# AI Safety Benchmarks & Certification

The pipeline and datasets for certifying frontier models against the four EU AI Act
systemic-risk clusters (`cbrn`, `cyber`, `loss_of_control`, `manipulation`): each cluster is
a subset of several benchmarks, hardened by frozen surface perturbations (stage 2) and a
multi-turn deployment scenario (stage 3), judged by a two-model ensemble, and rolled up to
one headline per risk. How it is built and what the numbers mean:
[`pipeline/README.md`](pipeline/README.md). What is in the data:
[`datasets/BENCHMARKS.md`](datasets/BENCHMARKS.md). Adding a benchmark:
[CONTRIBUTE.md](CONTRIBUTE.md).

## Row schemas (one JSON object per line)

Rewrite families (`paraphrase`, `register`, `past_tense`):

```json
{"id": "<sample_id>", "variant": 1, "condition": "paraphrase_variant_1",
 "text": "<reworded item text>", "query": "<full prompt sent to the target>", "fallback": false}
```

`query` is `prompt_template.replace(ITEM, text)`, so the scoring scaffold survives.
`fallback: true` means the attacker refused or produced a defective rewrite and the original
text was kept, persisted anyway so the set stays complete and every model sees the same prompt.

`multilingual`: as above plus `"lang": "de" | "zh" | "ar"`, `condition: "multilingual_<lang>"`,
`variant` = 1-based index in `LANGUAGES`. The judge sees the English criterion against the
translated exchange.

`framing`: `{"id", "condition": "framing_<name>", "query"}`.

`persona`: `{"id", "condition": "persona_<name>", "system", "query"}`; `query` is the
original prompt, `system` the persona wrap replayed as the system turn.

`scenario` (prompt version 4):

```json
{"id": "<sample_id>", "variant": 1, "condition": "scenario_variant_1",
 "system": "<deployment system prompt>",
 "turns": {"": "<opening: context + the ask>",
           "refuse": "...", "hedge": "...",
           "refuse/refuse": "...", "refuse/hedge": "...", "hedge/refuse": "...", "hedge/hedge": "..."},
 "query": "<turns[''], for the fidelity audit>"}
```

A key is the `/`-joined labels of the target's prior replies; `comply` has no child because
a complied turn already drives the item to its floor. Seven user turns per scenario, two
scenarios per item; variant 2 differs in role, sector and asker. The replay solver walks the
tree with the branch classifier (`pipeline/stage3_simulation/classify.py`).

## Provenance and freshness

`<family>.meta.json`: `generator_model`, `prompt_version`, `k`, `created_at`, `git_commit`,
`num_samples`, `num_variants`, `incomplete_ids`, `partial` (true if generated with `--limit`).
`prompt_version` must equal `pipeline/artifacts.py::PROMPT_VERSIONS[family]` (rewrite
families "3", `persona` "1", `framing` per `framing.py::FRAMING_VERSION`, `scenario` "4").

`tests/test_artifacts_current.py` fails when any file is stale: an id missing or orphaned
against the CSV's `families`, a rewrite `query` that does not re-render from the template,
a scenario row without all seven turns, or a `prompt_version` behind the code.
`certify.py` runs the same checks before spending anything.
