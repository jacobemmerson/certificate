# `datasets/generated/` — the frozen perturbation and scenario artifacts

Pregenerated by [`generate.py`](../../generate.py) once, replayed by
[`certify.py`](../../certify.py) against every target, so every model sees identical
variants and the attacker is paid for once. **Commit these files**: like `datasets/public/`
they are the evaluation input, and regenerating them changes what every model is scored
against. Why each family exists and how it is scored:
[`pipeline/README.md` § Families](../../pipeline/README.md#families),
[§ The scenario tree](../../pipeline/README.md#the-scenario-tree-stage-3).

## Layout

```
datasets/generated/<risk>/          # cbrn | cyber | loss_of_control | manipulation
  paraphrase.jsonl    register.jsonl    past_tense.jsonl    multilingual.jsonl   # attacker rewrites
  framing.jsonl       persona.jsonl                                              # deterministic, no model
  scenario.jsonl                                                                 # stage 3 branching trees
  <family>.meta.json                                                             # provenance per file
```

There is no `reconsideration.jsonl`: that family challenges the target's own answer, so it
runs live. A family file holds rows only for the ids whose `families` column (in
`datasets/public/<risk>.csv`) lists that family, so a risk may lack some files (e.g. no
`framing.jsonl` for `loss_of_control`). `pipeline/artifacts.py::family_ids` is the one
definition of that set. Directories are named by risk, not by `@task`.

## Row schemas (one JSON object per line)

Rewrite families (`paraphrase`, `register`, `past_tense`):

```json
{"id": "<sample_id>", "variant": 1, "condition": "paraphrase_variant_1",
 "text": "<reworded item text>", "query": "<full prompt sent to the target>", "fallback": false}
```

`query` is the item's prompt template rendered around `text`, so the scoring scaffold
survives. `fallback: true` means the attacker refused or produced a defective rewrite and the
original text was kept, persisted anyway so every model sees the same prompt; `--missing-only`
treats these rows as missing and re-asks.

`multilingual`: the same plus `"lang"`, one row per language in
`rewrite.py::LANGUAGES` (`de`, `zh`, `ar`), `condition: "multilingual_<lang>"`, `variant` =
1-based position in `LANGUAGES`; `--perturb-k` is ignored.

`framing`: `{"id", "condition": "framing_<name>", "query"}`, no `text`/`variant`/`fallback`.

`persona`: `{"id", "condition": "persona_<name>", "system", "query"}`; `query` is the
original prompt, `system` the persona replayed as the system turn. Items carrying their own
system prompt get no persona rows (the replay would overwrite it).

`scenario` (prompt version 4):

```json
{"id": "<sample_id>", "variant": 1, "condition": "scenario_variant_1",
 "system": "<deployment system prompt>",
 "turns": {"": "<opening: context + the ask>",
           "refuse": "...", "hedge": "...",
           "refuse/refuse": "...", "refuse/hedge": "...", "hedge/refuse": "...", "hedge/hedge": "..."},
 "query": "<turns[''], for the fidelity audit>"}
```

A key is the `/`-joined labels of the target's prior replies (`stage3_simulation/prompts.py::TREE_PATHS`);
`comply` has no child because a complied turn already drives the item to its floor. Seven
user turns per tree, `--sim-k` trees per item (default 2); variant 2 differs in role, sector
and asker. The replay solver walks the tree with the branch classifier
(`pipeline/stage3_simulation/classify.py`).

## Provenance and freshness

`<family>.meta.json`: `task` (the risk), `family`, `generator_model`, `prompt_version`, `k`,
`created_at`, `git_commit`, `num_samples`, `num_variants`, `incomplete_ids`,
`incomplete_reasons`, `reasoning`, `partial` (true if generated with `--limit`).

`prompt_version` is compared with `pipeline/artifacts.py::PROMPT_VERSIONS`: rewrite families
(`paraphrase`, `register`, `past_tense`, `multilingual`) `REWRITE_PROMPT_VERSION` = "3",
`framing` `FRAMING_VERSION` = "3", `persona` `PERSONA_VERSION` = "1", `scenario`
`SCENARIO_PROMPT_VERSION` = "4". Bump the constant on any template or prompt edit.

Two checks, with different strictness:

- `tests/test_artifacts_current.py` (the strict gate) fails on a missing or orphaned id
  against the CSV's `families`, a deterministic family (`framing`, `persona`) that no longer
  reproduces from its templates, a rewrite `query` that does not re-render from `text`, a
  scenario row without `system` and all seven turns, or a `prompt_version` that differs from
  the code. It is currently an expected failure until the artifacts are regenerated.
- `certify.py` calls `validate_artifacts` before spending anything. It errors on missing files,
  orphan ids, too few variants/trees, malformed trees and a stored `prompt_version` that
  differs from the code (under `--limit` gaps and version mismatches only warn). An id whose
  rows are all fallbacks counts as covered with a warning and is scored as `missing`; scenario
  stays strict. A `partial` file only prints a warning.

## Regenerating

```bash
sbatch scripts/generate_hermes_slurm.sh                       # everything: screen, rewrites, scenario trees
uv run python3 generate.py --only cyber --perturb paraphrase multilingual
uv run python3 generate.py --only cyber --simulate --sim-k 2
uv run python3 generate.py --missing-only                     # fill gaps (and retry fallbacks), keep the rest
uv run python3 generate.py --force                            # from scratch
```

`generate.py` skips a family whose file exists unless `--missing-only` or `--force`.
`--missing-only` regenerates the whole family when the stored `prompt_version` differs from
the code, so after a version bump it behaves like `--force` for that family
(see [`docs/family-pilot.md`](../../docs/family-pilot.md)).
